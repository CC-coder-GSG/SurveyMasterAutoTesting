# 测量大师 Android 冒烟自动化规划（SP81150709）

## 1. 目标

本文用于规划测量大师在安卓手簿 `SP81150709` 上的下一批冒烟自动化用例。规划重点是：

- 不重复当前仓库已有用例；
- 优先覆盖测量软件最关键、最容易在版本迭代中失效的功能；
- 用例可重复执行、断言明确、失败后容易定位；
- 首批尽量不依赖云服务、外部文件、GNSS 接收机、已知坐标点或人工确认；
- 不产生项目、测量点、设备配置等难以清理的持久数据。

## 4. 用例选择原则

推荐按以下顺序选择冒烟用例：

1. **纯离线、结果确定的计算功能**：最适合发现业务逻辑回归，且不依赖接收机和网络；
2. **核心数据页面的只读和可逆操作**：例如坐标系统读取、点库查询后清空；
3. **测量工作台就绪状态**：进入真实测量界面，但不点击测量按钮；
4. **配置页面只读契约**：校验关键选项加载，不切换持久化开关；
5. **外部依赖页面的前置页**：只验证格式、默认值和控件，不执行登录、导入、连接或注册。

不建议将云登录、真实接收机连接、真实点测量、文件导入导出、移动站/基准站设置放入第一批 CI 冒烟。它们更适合带独立标签的硬件集成或回归套件。

## 5. 推荐冒烟用例

### 5.1 P0：建议首批实现

#### SMK-CALC-001 角度转换结果正确

- 路径：工具 → 角度转换；
- 前置：App 已进入项目主页，无网络和接收机要求；
- 操作：选择“度”或当前可稳定输入的角度格式，清空输入框，输入 `180`，点击“计算”；
- 核心断言：度数约等于 `180`、弧度约等于 `π`、百分度约等于 `200`，度分秒结果代表 `180°00′00″`；
- 自动化方式：使用 `ANGLE_FORMAT_SPINNER`、`ANGLE_INPUT`、`CALCULATE_BUTTON`、四个结果 resource-id；对结果去单位后按数值容差比较，不依赖展示末尾零位数；
- 清理：返回工具主页，输入值不落库；
- 不重复说明：现有用例只确认“角度转换”入口可见，没有进入页面和验证计算结果。

这是首批价值最高的用例：输入确定、结果确定、无外部依赖，能同时验证页面交互和核心计算逻辑。

#### SMK-PROJ-001 当前项目坐标系统可完整读取

- 路径：项目 → 坐标系统；
- 操作：读取坐标系名称、源椭球、目标椭球、投影方式，以及七参数、平面校正、高程拟合等区域；
- 核心断言：页面标题和关键区域存在；坐标系名称、源椭球、目标椭球、投影名称均为非空；返回后仍处于同一个项目；
- 自动化方式：复用 `CoordinateSystem.resource` 中的唯一 resource-id；动态项目值只断言非空，不硬编码为 `CGCS2000`；
- 禁止操作：不点击“确认”，不修改参数；
- 不重复说明：现有核心导航只确认项目主页上的“坐标系统”图标可见。

#### SMK-PROJ-002 坐标点库查询可恢复

- 路径：项目 → 坐标点库；
- 前置：不要求点库中预先存在固定点；
- 操作：记录列表当前行数，在查询框输入唯一不存在值 `__AUTO_SMOKE_NOT_FOUND__`，确认筛选生效，再清空查询；
- 核心断言：点名、北坐标、东坐标表头正常；筛选过程页面不崩溃；清空后列表行数恢复为执行前值；
- 自动化方式：使用 `SEARCH_INPUT`、`POINT_LIST` 和三个表头 resource-id，基线行数在用例运行时动态采集；
- 清理：必须清空查询框并返回；
- 禁止操作：不点击导入和添加，不依赖固定点名；
- 不重复说明：仓库暂无坐标点库测试。

#### SMK-MEAS-001 未连接状态下点测量工作台可就绪

- 路径：测量 → 点测量；
- 前置：接收机未连接，执行前通过首页状态卡确认；若状态不符则明确跳过，而不是主动断开现场设备；
- 操作：进入点测量工作台，只读取界面；
- 核心断言：显示“点击此处连接设备”；地图根容器、设置、点库、图层、点名、代码和测量按钮均已加载；返回后测量主页可用；
- 自动化方式：复用 `MeasureMap.resource` 中的稳定 resource-id，以组合控件代表页面就绪；
- 禁止操作：不得点击测量按钮、改变点名、改变天线高或连接设备；
- 不重复说明：现有用例只在测量主页确认“点测量”入口可见，未验证工作台实际加载。

#### SMK-SET-001 软件设置关键配置可读取且无意外改变

- 路径：项目 → 软件设置；
- 操作：读取单位和小数位、坐标顺序、测量放样、显示设置、屏幕方向、界面风格、多语言，以及三个开关的当前状态；返回并重新进入；
- 核心断言：关键设置项均可见；重新进入后开关状态与首次读取一致；
- 自动化方式：复用 `SoftwareSettings.resource`，将开关状态作为运行时快照比较；
- 禁止操作：不点击任何开关，不改变语言、方向或界面风格；
- 不重复说明：仓库暂无软件设置详情页用例。

#### SMK-APP-001 前后台切换后业务上下文可恢复

- 路径：从项目主页将 App 置于后台 3 秒，再恢复前台；
- 核心断言：包名仍为目标 App；当前项目标题未改变；底部导航和项目主页关键控件可交互；无隐私协议或权限弹窗异常重现；
- 自动化方式：使用 Appium 的后台/激活应用能力，恢复后使用条件等待，不使用固定长等待；
- 清理：回到项目主页；
- 不重复说明：已有 sanity 只验证首次打开和关闭，没有验证运行中恢复能力。

### 5.2 P1：P0 稳定后加入

#### SMK-DATA-001 数据导入/导出格式契约可用

- 分别进入数据导入和数据导出前置页；
- 断言格式列表存在，至少可识别 CASS、名称/N/E/Z CSV 等基础格式，下一步按钮存在；

- 复用 `DataTransfer.resource`，导入和导出建议拆成两个测试，便于定位失败。

#### SMK-PARAM-001 参数计算页面结构可用

- 进入参数计算，断言坐标转换方法、高程拟合方法、控制点/测量点表头、结果区域存在；
- 不添加控制点，不点击“应用”；
- 若产品对空数据点击“计算/匹配”有稳定提示，可在后续增加“空数据防护”断言，但不要把 Toast 文案作为第一版唯一断言。

#### SMK-CODE-001 代码管理默认代码集可读取

- 进入代码管理，断言代码组下拉框、当前组名和代码列表加载成功；
- 当前组名只断言非空，不硬编码具体模板；
- 不点击添加、删除或组管理确认操作。

#### SMK-EQP-001 连接设备页默认配置正确但不发起连接

- 路径：设备 → 连接设备；
- 断言接收机 Tab、外设 Tab、设备类型、连接方式、目标设备和连接按钮加载；
- 在标准环境下断言默认设备类型为 RTK、默认连接方式为蓝牙；目标设备名称从环境变量读取；
- 不点击连接按钮；
- 与现有司南万象稳定性用例的差异：本用例只检查连接前配置契约，不进行真实硬件连接。

### 5.3 暂不纳入日常冒烟

以下场景业务重要，但外部状态或清理成本较高，建议使用独立标签：

| 场景 | 建议套件/标签 | 暂缓原因 |
| --- | --- | --- |
| 新建、修改、删除项目 | `regression`, `writes_project` | 已有新建覆盖；需建立可靠清理机制后再扩展 |
| 实际点测量、点放样 | `hardware`, `writes_point` | 依赖定位状态并写入点库 |
| 移动站、基准站、司南万象 | `hardware`, `receiver_config` | 会改变接收机状态，且已有连接稳定性测试 |
| 云服务登录/上传/下载 | `network`, `cloud` | 依赖账号、网络和服务端状态 |
| 文件导入导出全流程 | `file_io` | 依赖预置文件、系统文件选择器和产物清理 |
| 注册信息写入 | `license`, `destructive_config` | 可能影响授权状态，不适合作为普通冒烟 |
| 软件设置切换 | `settings_write` | 语言、方向、快捷键会影响后续用例 |

## 6. 自动化实现约束

### 6.1 分层落地

继续遵守仓库现有分层：

```text
tests/smoke/                         # 只写 Given / When / Then 和业务断言
resources/keywords/flows/            # 跨页面流程与恢复流程
resources/keywords/pages/<module>/   # 单页面操作、取值、页面就绪检查
resources/locators/android/          # 集中管理定位器
```

建议新增：

```text
tests/smoke/OfflineCalculationSmoke.robot
tests/smoke/ProjectDataReadOnlySmoke.robot
tests/smoke/MeasureWorkspaceSmoke.robot
tests/smoke/AppRecoverySmoke.robot

resources/keywords/pages/Tools/AngleConversion.resource
resources/keywords/pages/Project/CoordinateSystem.resource
resources/keywords/pages/Project/PointStore.resource
resources/keywords/pages/Project/SoftwareSettings.resource
resources/keywords/pages/Measure/PointSurvey.resource
resources/keywords/flows/ReadOnlySmoke.resource
```

优先复用已经存在的 locator 文件。只有实机确认缺少 resource-id 时才新增定位器；不要使用屏幕坐标，因为 H55 与仓库原 R60 采集设备的尺寸和系统版本可能不同。

### 6.2 标签建议

每条用例至少包含 `smoke`，并按依赖补充：

- `offline`：无网络依赖；
- `read_only`：不写业务数据；
- `calculation`：纯计算；
- `requires_disconnected_receiver`：要求接收机未连接；
- `hardware`：会使用接收机，不进入默认 CI 冒烟；
- `network`：依赖云端，不进入默认 CI 冒烟。

默认 CI 可先执行：`smoke AND (offline OR read_only) AND NOT hardware AND NOT network`。

### 6.3 等待、断言与证据

- 点击前等待目标控件可见且可交互；点击后等待下一页面的唯一就绪控件；
- 不使用 `Sleep` 驱动流程；前后台切换的 3 秒是业务动作参数，恢复仍使用条件等待；
- 每条用例至少有一个业务断言，不能只以“未报错”作为通过条件；
- 动态数据采用非空、格式、前后快照或运行时基线断言；
- 计算结果采用数值容差，不比较易变化的格式化字符串；
- 失败时保存截图、页面 XML、当前 Activity、App 版本、设备连接状态；
- 每条测试结束都回到项目主页，异常时由全局 teardown 兜底恢复。

### 6.4 测试数据与状态隔离

- 不依赖固定项目名。运行时记录当前项目名，并在结束时确认未改变；
- 查询用不存在的唯一字符串，结束时清空；
- 不依赖点库必须为空或必须存在某个点，使用查询前后的动态行数；
- 目标接收机名称从环境变量读取，不写死在 page 或 flow 文件中；
- 首批不清除 App 数据，保持 `noReset=true`；首次启动协议和权限由统一 session 关键字处理。

## 7. 执行环境需要先修正的问题

当前仓库的设备配置与本次实机不一致：

- `resources/variables/env_test.yaml` 当前是 `SP84650578`；
- `_sanity_open_app.robot` 当前硬编码的是 `4e83cae7`；
- 本次目标设备是 `SP81150709`。

实现新用例前应统一由变量文件或 CI 参数传入 UDID，并移除测试文件内的硬编码设备号。建议执行前置检查：

1. `adb devices` 中目标 UDID 唯一且状态为 `device`；
2. 目标包 `com.sinognss.sm.free` 已安装；
3. 记录实际 `versionName/versionCode` 到 Robot 报告；
4. 当前前台若是其他测量 App，必须按包名激活测量大师；
5. 对 `requires_disconnected_receiver` 用例只检查状态，不主动断开现场正在使用的接收机。

## 8. 推荐实施顺序与验收标准

### 第一批：稳定离线集

实施 `SMK-CALC-001`、`SMK-PROJ-001`、`SMK-PROJ-002`、`SMK-SET-001`、`SMK-APP-001`。

验收标准：

- 单次全部通过；
- 连续执行 10 次无偶发失败；
- 每次执行后当前项目、点库数据和设置状态不变；
- 单轮目标时长不超过 4 分钟；
- Robot 报告能明确指出输入值、实际结果和失败页面。

### 第二批：业务工作台只读集

加入 `SMK-MEAS-001`、`SMK-DATA-001`、`SMK-PARAM-001`、`SMK-CODE-001`。

验收标准：默认离线环境可执行；依赖状态不满足时必须显示明确 skip 原因，不能误报失败或自动改变设备状态。

### 第三批：设备配置前置检查

加入 `SMK-EQP-001`，并与现有司南万象稳定性用例分开调度。前者属于只读冒烟，后者属于硬件稳定性测试。

## 9. 最终建议

最值得优先落地的是“角度转换真实计算 + 坐标系统读取 + 点库可逆查询 + 设置只读快照 + 前后台恢复”这 5 条。它们没有覆盖现有用例已经验证的主导航和新建项目流程，同时具备较强的业务代表性、清晰断言和较低环境依赖，适合作为 `SP81150709` 上第一组稳定冒烟自动化基线。
